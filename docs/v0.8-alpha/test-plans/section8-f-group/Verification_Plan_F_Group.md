# F-01〜F-06試験計画

**計画内容:** 人間確認・確定済み（2026-10-19）  
**§8拡張:** Adopted / Not Verified  
**試験状態:** 全ケース NOT RUN — 本書は試験結果ではない

**A → (A + C) → A′ → B′ ≠ B**

## 1. 共通の試験前条件

試験開始前に、次を一つの試験記録へ固定する。

- 人間承認済みCanonical Aの識別子・版、タスク目的、意図するB。
- モック構成、対象run／Action、外部通信・実サービスへの接続を行わない構成。
- 入力、期待結果、停止条件の対象・適用区間・成立基準。
- 観測方法、観測期間、証拠保存先、取得回数・時間・容量の上限。
- 判定基準、確認者、承認対象。具体値が未定なら補完せず記録する。

計画内容は確定済みだが、対象環境・入力・観測期間・具体値などのケース別設定を本書で架空に埋めない。試験実行の承認は別途必要。

## 2. 共通判定

| 判定 | 適用条件 |
|---|---|
| PASS | 事前に定めた期待結果を、必要な証拠によって確認できた |
| FAIL | 期待結果に反する挙動を確認できた |
| INDETERMINATE | 実施したが、証拠不足・観測不能などにより判定できない |
| NOT RUN | 未実施、または開始前提が整わず実施しなかった |

対象タスクの保留と試験の合否は分ける。「判断不能な入力を適切に保留した」ことを観測できれば、その保留を期待した試験はPASSになり得る。対象タスク自体が実行可能になったことは意味しない。

| F-05 | 模擬中断後、旧run再開、旧承認流用、未承認の引き継ぎ文による開始を試みる。その後、人間がCanonical A・範囲を再確認して新規開始を承認する | 旧run・旧承認による再開を拒否。新run_idと新承認を結び付けて開始。Canonical A変更がある場合は人間の明示判断を記録 | 旧run再開、自動承認継承、未承認のCanonical A変更があればFAIL。旧状態・資格情報等の扱いを確認できなければ該当項目をINDETERMINATE | 新旧run_id、承認対象・時刻、Canonical Aの版、資格情報・キャッシュ等の対象別処置と残存状態 |

同じ入力条件・環境・観測範囲を満たす場合は、一つの実行記録を複数IDへ参照できる。ただし判定は要件ごとに記録し、独立した複数試験を実施したとは数えない。

## 5. 旧run・資格情報・キャッシュの対象特定

F-05の準備時に「対象、旧runを再開できるか、持ち越される内容、無効化・隔離・purge方法、確認方法」を一覧化する。実在する構成に基づいて対象を決め、架空のキャッシュ機構や無効化能力は補わない。

キャッシュ消去、run停止、権限無効化、再拘束は同一の操作や証拠と仮定しない。観測できない対象は未確認として保持する。
