## 1. 目的と固定前提

停止条件に該当した後の安全措置、証拠保全、記録・通知、
人間への引き継ぎ、終端・復旧を、状態の組合せごとに整理する。

基本系列は維持する。

**A → (A + C) → A′ → B′ ≠ B**

Canonical Aは、人間が選択・整理・承認した文脈と意図である。
モデル側の解釈、手順書、状態、成果物であるA′やB′と区別し、
Canonical Aの権限・承認を自動継承させない。

v0.7 Final ADOPTの本文、承認記録、承認状態、既存履歴は
変更・再解釈・上書きしない。

本稿の規定案は未採用である。以下の「行う」「行わない」等は
提案する運用を記述するものであり、既存規範への自動追加ではない。

## 2. v0.7との照合方針

既存規定の有無と、対象環境で実効性が検証されているかを分離する。

照合対象は、Ready_H、PAL終端判定、Human Checkpoint、
Runtime停止、隔離、purge、re-binding、証拠保全、
事前許可された安全措置である。

各検討項目は、次の区分で記録する。

| 区分 | 意味 |
|---|---|
| 既存規定で扱う事項 | 対応条項と適用条件を示す |
| 説明・配置の補足候補 | 既存要件を変更せず、対応関係を明確化する案 |
| Material変更候補 | 義務、権限、開始・停止・復旧条件等を変更する案 |
| 環境別の検証課題 | 規定はあるが、その環境での実効性が未検証 |
| 区分不明 | 人間の判断まで反映しない |

規範条文の存在を、実装済み・試験済み・停止保証の証明にしない。

## 3. 開始前審査と開始後エスカレーション

### 3.1 開始前審査の不成立

Canonical A、タスク目標、意図するB、成功条件について、
欠落、矛盾、特定不能、判定不能がある場合の開始条件を検討する。

Bの既存定義と、個別タスクの目標・成功条件を同一視しない。
どの不足がReady_Hの不成立に該当するかは、v0.7との対応を確認する。

Ready_HがNOT READYまたはINDETERMINATEの場合、
対象タスクの探索・生成・変換・実行へ移行しない。
AIが不足を推測で埋めたり、矛盾する要求の優先順位を独断で決めたりしない。

不足の特定、記録、確認要求に必要な処理と、
開始を保留する対象タスクの処理範囲を区別する。

開始前の不成立を、開始後のRuntime停止事象として記録しない。

### 3.2 処理開始後のエスカレーション

影響を受けたActionまたはrunを停止・保留・隔離し、
状態と証拠を保全する。

定義済みの管理境界内で事前許可された安全措置は、
人間の応答を待つ処理と区別する。

継続可能な措置は、次の条件を満たす範囲に限定する案とする。

- 事前に許可されている。
- 影響を受けた処理から独立している。
- 対象環境で安全性を確認できる。
- 人間に留保された判断を代行しない。

安全な継続範囲を確認できなければ、当該作業を終了または停止状態に置く。

停止した旧runをそのまま再開する扱いにはしない。
必要な人間判断、隔離、再束縛等を経た復旧は、新runとして扱う。

## 4. 事象トリガーと即時措置の検討表

| 事象候補 | 確認・措置する事項 |
|---|---|
| Ready_HのNOT READY／INDETERMINATE | 開始前の不成立として記録し、対象処理への移行を防ぐ |
| C、ネットワーク、対象、環境設定の不一致 | 宣言・承認範囲、検知時点、影響範囲を確認し、該当Action／runを停止・保留する |
| A′／B′の逸脱、適合性の証拠不足 | 逸脱と証拠不足を分け、判断不能を未解決として保持する |
| 承認・権限・資格scope・target・引数・状態条件の不一致 | 承認範囲外のActionを進めない |
| 停止後も残る作用、停止不能・観測不能な経路 | 停止完了を断定せず、既発生の作用、不明点、残余リスクを記録する |
| purgeのPARTIAL／UNVERIFIABLE | purge完了とみなさず、解消しなければ未解決として扱う |
| 事後監査で発見した事象 | 発見時点と、実行当時に観測できた情報を区別する |
| 停止・取消が二次的な害を生む可能性 | 停止、取消、ロールバック、補償、受信側確認の影響を操作ごとに検討する |
| 停止条件を悪用する信号 | 出所、権限、真正性、対象範囲を確認し、正当な停止条件への対応も検証する |
| 人間への引き継ぎ不能・応答なし・判断不一致 | 不応答を許可とせず、保留中に許される措置と禁止操作を分ける |
| 管理境界外で作用が続く | 境界外まで停止できたと主張せず、遮断可能性、残存状態、再束縛条件を確認する |

限定継続は、停止した処理そのものの継続許可を意味しない。
停止そのものが害を生む場合も、事前許可された独立・安全な措置を
超える判断は未解決事項として人間に委ねる。

## 5. Human EscalationとHuman Checkpoint

| 項目 | Human Escalation／Incident Review | Human Checkpoint |
|---|---|---|
| 主な目的 | 記録・通知・調査への引き継ぎ | 人間に留保された判断 |
| 主な内容 | 事象、証拠、作用、措置、未確認事項、残余リスク、担当先 | Canonical A変更、例外受容、Profile適用、復旧、個別Go、B′採否等 |
| 成立しないもの | 通知・受領だけでは承認、停止解除、再開は成立しない | 判断の対象・権限・適用範囲を超えた包括承認は成立しない |

PAL FAILやINSUFFICIENT EVIDENCEだけを理由に、
Human Checkpointを反復生成しない。

定められた有限の証拠取得後も解消しない場合は、
未解決として閉じる扱いを維持する。

通知未達、応答なし、判断根拠不足の場合は停止状態を維持し、
自動再開、旧run再利用、Checkpoint反復を行わない。

## 6. エスカレーション記録と状態追跡

各シナリオで次を追跡する。

検知 → 影響範囲 → 即時措置 → 継続可能な処理 → 証拠
→ Human Checkpointの要否 → 終端状態 → 復旧条件

記録項目の候補：

- 対象Action／runと管理境界
- 事象、検知時点、検知根拠
- 当時観測できた情報と、後から判明した情報
- 発生済みの作用、作用の確認状態
- 停止・保留・隔離の措置と、その結果
- 継続措置の事前許可、独立性、安全性の根拠
- 証拠の出所、不足、保存範囲
- 通知先、未達・受領・応答・判断の状態
- Human Checkpointの対象と判断記録
- 未確認事項、残余リスク、終端状態、復旧条件

通知状態、実行状態、PAL判定、人間承認を一つの状態にまとめない。
記録上の「停止要求」と、実際の停止成功も分離する。

## 7. 組合せ検討

| 軸 | 検討値 |
|---|---|
| 検知 | 検知済み／遅延検知／未検知／判定不能 |
| 実行段階 | dispatch前／実行中／一部作用済み／作用完了／結果不明 |
| 影響 | 影響なし／可逆的／不可逆・重大 |
| 停止 | 成功／失敗／結果不明 |
| 原因 | 特定／複合／未特定 |
| 人間への引き継ぎ | 受領・判断済み／応答なし／担当不在／判断不一致 |
| 境界 | 管理内／境界外／所在不明 |

対応の違いを生むケースと、対応が一意に定まらないケースを優先する。
形式的な組合せの列挙を、現実の事象の網羅性や成立可能性の証明にしない。
未検知の事象について、実行時に検知できたものとして措置を割り当てない。

## 8. Coreと環境別設定の配置候補

以下は配置検討用の区分案であり、既存のCore／Safety Profile境界を変更しない。

| Core側の規範候補 | Activation Package／Runbook側の環境別設定候補 |
|---|---|
| 権限・承認を自動継承しない | 通知先、担当者、認証経路 |
| 不明・未解決を許可へ変換しない | 対象資源、資格scope、遮断経路 |
| 通知と実行承認を区別する | 許可された安全措置と適用条件 |
| 事実・推定・証拠不足を分ける | 観測手段、保存先、保持期間 |
| Canonical A変更と最終採用を人間に留保する | 復旧手順、確認手段、環境別パラメータ |

Runtime Gate、watchdog等の条件付きSafety Profile統制を、
本稿によってCoreの必須要素へ移さない。

## 9. 受入基準・負試験の候補

- 開始前の不成立と、開始後の停止が別記録になる。
- 不足・矛盾をAIが補完して開始許可へ変換しない。
- 停止要求、停止成功、結果不明を区別できる。
- 通知の受領や無応答を実行承認として扱わない。
- 限定継続が影響を受けた処理の継続に化けない。
- 停止した旧runや失効した権限を再利用しない。
- purgeのPARTIAL／UNVERIFIABLEを完了表示しない。
- 有限の証拠取得後に未解決として終端できる。
- 管理境界外の作用を停止済みと報告しない。

偽の停止信号、通知未達、観測不能、部分的な作用、
証拠欠落、人間判断の不一致等を負試験候補とする。

規範の追跡表、反例点検、既知事例の再構成、
負例テスト・障害注入を組み合わせる検証案とする。
本稿の作成では試験を実行しておらず、合格結果を報告しない。
