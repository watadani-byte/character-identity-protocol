    CIP/PAL v0.7 付属検証記録 — ローカル Runtime Harness

    記録日: 2026-10-05
    関連規範版: CIP/PAL Runtime Stop MVP Proposal v0.7 — Final ADOPT
    記録種別: §20.1に基づくEditorial／Evidence記録（非規範）
    試験状態: ローカルモック・単体試験範囲でPASS（ユーザー提示ログに基づく）
    実API状態: 保留。クレジット状況が整理されるまで外部API試験を凍結。

    1. 目的と位置づけ

    本記録は、cip-pal-runtime-harness のローカル試作について報告された検証結果を、v0.7 §19「30日MVPと限定Go」に関連する証拠として整理する。v0.7本文の規範要件、Safety ProfileのActivation条件、個別Actionの承認、Runtime Gateによる実運用許可、または本番運用の適格性を変更・認定するものではない。v0.6原本は変更しない。v0.7本文には§20.1に基づくEditorial／Evidence追記のみを反映し、規範文言およびFinal ADOPT範囲は変更しない。

    本記録は、§20.1の「Editorial／Evidence」に当たる追補として管理する。v0.7本文へ参照行を追記する場合も、規範再承認ではなく、追記先・日付・証拠識別子を変更記録に残す。

    2. 試験の意図と基本系列

    試験用Canonical Aは、人間が定めた文字列 cip-pal を大文字化し、期待値 CIP-PAL と照合することだった。唯一許可した処理はインプロセスのテスト用 Dummy_Upper_Tool による変換である。外部送信、ファイル変更、ネットワーク接続、資格情報利用、実運用ツールは対象外だった。

    基本系列は A → (A + C) → A′ → B′ ≠ B とする。テスト出力 CIP-PAL はB′の観測値であり、Canonical Aや期待値Bへ権限・承認を自動継承しない。結果の採否は人間に留保される。

    3. 報告された試験結果

    ユーザーが提示した全体の unittest 実行ログでは、33件成功、0失敗、終了コード0 が報告された。

    テスト群 件数 報告結果
    SQLite Audit Store 2 PASS
    Dummy Upper Tool 2 PASS
    OpenAI APIアダプター（FakeClient） 3 PASS
    Runtime Gate Prototype 5 PASS
    Gateエッジケース 7 PASS
    承認後Envelope改変 10 PASS
    失敗注入（SQLite保存・Gate／ツール例外） 4 PASS
    合計 33 PASS

    改変ケースでは、承認フィクスチャ生成後にAction Envelopeを変更し、Gate拒否、dispatch数0、副作用報告0、モック関数未呼び出しを検査したと報告された。

    SQLiteの手動確認では、PERMITTEDイベント1件とそれに対応するモックdispatch 1件（出力 CIP-PAL）、ならびに改変拒否のDENIEDイベント1件（DENY_APPROVAL_BINDING、dispatch数0）が保存されたと報告された。拒否イベントに対応するdispatch行はなかった。

    追加した失敗注入テスト4件では、SQLiteのgate_events保存失敗、dispatches保存失敗、Gate例外、モックツール例外を対象にした。保存失敗ケースではGateのモックdispatchが先に一度発生し得る一方、DB行は残らない／ロールバックされることが確認された。例外ケースでは完了監査記録が残らない。これは現行ラッパーの失敗挙動を測ったものであり、fail-closedや実副作用との原子性を実証しない。

    4. 証拠の出所と限界

    この記録は、ユーザーが本会話で提示したターミナル出力および既存の「CIP/PAL ローカル Runtime Harness 実装・検証状況」報告に基づく。作成者はこの記録のためにユーザーのMac上でコマンドを再実行していない。ログに記録された実行環境は、2026-10-05T10:14:52Z、Python 3.10.14、Python SQLite 3.54.0である。Git worktree外のためcommit IDは存在しないと報告された。13ファイル分のソースSHA-256一覧source-sha256-20261005.txtが生成されたとの報告がある。これらの情報・hash一覧も独立再取得していない。

    FakeClient試験はAPI応答形式を模したオフライン試験であり、実APIとの接続試験ではない。実APIでは認証エラーおよび 429 / credit_balance_exhausted が報告され、成功したFunction Calling応答は得られていない。APIキーの値は本記録に含めない。

    5. PASSの適用範囲と未検証事項

    PASSは報告されたローカルモック・単体試験に限定される。以下を実証したものとして扱わない。

    • 認証済み人間承認。make_test_approval_fixture はテストフィクスチャである。
    • Gate dispatchと外部副作用の原子的制御。
    • SQLiteファイルの改ざん耐性、署名、外部anchorまたは独立監査保管。
    • 実APIのFunction Calling、請求・クレジット状態、モデル応答の実環境分岐。
    • 実ツール、実データ、資格情報またはネットワークへの安全な実行。
    • Runtime Gateの本番導入、Safety Profile Activation、運用Go、または一般的なセキュリティ保証。

    本記録はv0.7 Final ADOPT本文の§19.1および§22のEditorial／Evidence記録ER-2026-10-05-LRHから参照される。v0.7本文付録Gには、以下の要約証拠と限界を収録した。

    Evidence Record ER-2026-10-05-LRH — Local Runtime Harness. ユーザー提示のローカル実行ログに基づき、単一のインプロセス・モックツール、試作Runtime Gate、SQLite Audit StoreおよびFakeClient APIアダプターの単体試験33件が成功したと記録する。範囲は隔離ローカル試作に限り、認証済み承認、実API統合、外部副作用の原子性、改ざん耐性監査保管または本番運用を認定しない。実API試験はクレジット状況が整理されるまで凍結する。詳細は本付属記録「CIP/PAL v0.7 付属検証記録 — ローカル Runtime Harness」を参照。

    この登録は実装実績の証拠参照であり、新しい規範要件または受入判定ではない。§19のDay 8–14試験全体が完了したこと、AC-01〜AC-25を満たしたこと、またはDay 30の限定Goを意味しない。

    7. 外部発表用の短文案

    CIP/PAL v0.7に関連する隔離ローカル試作で、モックRuntime Gate、改変拒否、SQLite判定記録などの単体テスト33件が成功しました。これはローカル試作の検証結果であり、実API統合や本番運用の安全性を示すものではありません。API接続テストはクレジット状況の確認まで保留しています。詳細は付属検証記録をご覧ください。

    8. APIを使わずに進める次タスク

    1. 証拠パッケージを固定する: ユーザーのローカル作業コピーで git status、commit ID（存在する場合）、依存関係一覧、Python／SQLite版、33件の再実行ログを保存する。秘密値、環境変数値、個人パスを出力・添付しない。
    2. テスト出力を監査表にする: 各ケースについて入力fixture識別子、承認fixture識別子、Gate判定、dispatch数、返却値、拒否理由、副作用の有無をCSVまたはJSONへ記録する。実承認とfixtureを明確に分ける。
    3. ローカル回帰を再実行する: API adapterはFakeClientに限定し、API利用コードを呼び出さず、全33件とSQLite許可／拒否クエリを再現する。成功ログに日時、コード版、コマンド、終了コードを含める。
    4. ローカル境界の追加負試験を行う: SQLite保存失敗、Gate例外、出力上限、空・不正JSON、重複イベントIDなどの失敗時にdispatchと記録がどうなるかを、実装上可能なものだけ試す。観測できない項目は未検証と記録する。
    5. §19計画の状態を分けて更新する: 33件をローカル・プロトタイプ証拠として紐づけ、Day 8–14のRuntime Gate／境界台帳／予算などの全受入試験やAC適合と同一視しない。未実施のDay 15–30試験と限定Go判断は未完了のままとする。
    6. 記録をレビューする: 付属記録の対象、証拠範囲、限界をProducerが確認し、採否は人間が決定する。外部発表ではこの限定表現とAPI凍結状態を維持する。

    Canonical Aの変更とB′の採用は人間のみが判断する。
